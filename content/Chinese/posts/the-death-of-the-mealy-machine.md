为什么米利机（Mealy machine）会在我的手稿里盘桓这么久？

因为它是第一个完美编码了我核心执念的形式化对象；正因如此，哪怕它的工具寿命早已耗尽，我依然迟迟无法放手。

翻看草稿与讨论记录的数字轨迹，这种不舍昭然若揭。在准备笔记里，裁决早已写得清清楚楚：

```text
§3.2 Mealy notation | M = (Q, Σ, Δ, δ, λ, q₀) | Drop
App A.1 | Theorem 1 + Mealy proof | Drop
```

它早已被标上了“删除”。甚至连审稿辅助智能体都一针见血地指出了它的冗余：*“米利机的结论不过是静态证书在零割（zero-cut）下的平凡特例”*——比后续建立的定理严格更弱、更不一般、也更不严谨。然而，就像机器里的幽灵一样，它一次又一次地借尸还魂。它游荡在 `2026jan.tex` 里，盘踞在 `Desktop/cc.tex` 中，又悄无声息地溜回了 AIES 的投稿版本。每一次切除它的尝试都以失败告终；它总是能活下来。

说到底，米利机从来不只是关于人工智能的归责问题，它关乎一种个人的认识论执念。它精准地形式化了贯穿我所有论文的那道结构性边界：

| 论文 | 同一种执念的不同衣装 |
| :--- | :--- |
| **ccModel / 2026jan** | 米利机：输出映射 $\lambda$ 非单射 $\to$ 不存在从观测输出重构内部状态的解码器。 |
| **Double Certificates** | $\varepsilon_{\text{state}}^{\text{UB}}$：内部隐状态信息向公开轨迹泄漏的最小割上界。 |
| **cascade/paper** | 认识论边界：证明仅凭输出审查无法重构内部执行状态。 |
| **POPL d-separation** | 作为 `Prop` 命题的 `Reachable` 与作为 $\Sigma$-类型的 `StaticRoute`——揭示可达性如何掩盖了必须被反编译的内部路径结构。 |
| **Liability Paradox** | 核心论断：没有任何有限长度的观测序列能够唯一确定内部状态。 |

真正吸引我的从来不是自动机理论本身，而是那个“观测无法重构原因”的切肤瞬间。米利机是对这种失效最极简、最优雅的漫画式勾勒：一个藏着隐秘齿轮的封闭黑箱，摇动曲柄产生输出，而完全相同的输出序列却可能由多组截然不同、彼此不相容的内部齿轮构型所生成。

![藏着隐秘齿轮的封闭黑箱](/images/mealy-machine/hidden-gears.jpg)

但米利机的悲剧也正在于它的简单。它只能给出一个生硬的二元裁决——由非单射直接跳向不可判定——而我们真正需要的，是对认识论损耗进行分级、构造性且可反编译（decompilable）的刻画。

这正是 POPL 论文最终完成的事情。它用机械化的见证提取器（witness extractor）取代了关于“状态不可恢复”的挥手式论证。通过 `route_improves_of_bad` 的良基度量、`StaticRoute` 见证提取器以及 `dSeparated_iff_dSeparates` 的互模拟等价，POPL 论文正是彻底成年的米利机。

迟迟舍不得删掉米利机，是对那个最初让这一执念变得清晰可读的对象的眷恋。但“清晰可读”不等于“严格”。POPL 论文标志着它终于找到了真正属于它的形式化归宿——从自动机理论走向因果图，从散文式证明走向 Lean 4，从二元的不可判定性走向显式的见证提取。

米利机必须死去，`route_improves_of_bad` 才能诞生。
